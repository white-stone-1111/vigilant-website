Quickstart

Go from zero to a live testimonial widget on your site in about five minutes. You'll create a space, add your first testimonial, and embed it — no backend required.

Prerequisites

  • An Endors account — request access if you don't have one yet.
  • A page where you can paste a <script> tag (any stack works: plain HTML, React, Webflow, Framer…).

1. Create a space

A space holds all the proof for one product or client. In the dashboard, click New space, give it a name, and copy the space ID — it looks like spc_9x2 and you'll need it in a moment.

Tip

One space per client or product keeps widgets, forms and analytics cleanly separated. See the API overview for the full model.

2. Add your first testimonial

Inside your space, open Testimonials → Add manually and paste in a quote from a happy customer, with a name and optional rating. Approve it so it becomes eligible for widgets — only approved testimonials are rendered.

You can also send the space's collection link to customers so proof comes to you, but one manual entry is all we need for this quickstart.

3. Embed the widget

Create a widget in Widgets → New widget, pick the Wall layout, then paste the snippet it gives you into your page, right before the closing </body> tag:

index.html 
<!-- where the widget should render -->
<div data-endors-widget="wdg_4fk"></div>

<!-- once per page, before </body> -->
<script
  src="https://cdn.endors.io/widgets/v1.js"
  data-space="spc_9x2"
  data-key="pk_live_4f9d8c2b7a1e"
  async
></script>
Public keys only

The snippet uses a public key (pk_live_…), which is safe to expose in the browser. Never put your sk_live_… secret key in client-side code.

4. Verify it works

Reload your page — the widget renders approved testimonials from your space within a second or two. If nothing shows up, work through this checklist:

  1. The testimonial is approved, not pending.
  2. The data-space attribute matches your space ID.
  3. The browser console shows no 403 — that means the wrong key type was used.
Working locally?

Widgets render on localhost out of the box — no domain allow-listing needed until you go to production.
