The data model

Four objects make up everything in Endors. Each guide should open by situating the reader in the model before diving into specifics:

  • Space — a container for proof about one product or client. Most accounts have a handful.
  • Testimonial — a single piece of proof: text, rating, author, media, status.
  • Widget — a rendered, filtered view of a space that you embed on a page.
  • Webhook — a subscription that pushes changes to your backend in real time.

The widget lifecycle

Use the steps component whenever a process has a natural order. Nemo enim ipsam voluptatem quia voluptas sit aspernatur aut odit aut fugit:

Collect

Send a collection link, embed a form, or import from CSV, Google reviews or a spreadsheet. Everything lands in the review queue.

Curate

Approve, reject or tag submissions. Only approved testimonials are eligible for rendering in widgets.

Render

Widgets pull approved items over a CDN-backed feed and render them with your theme — wall, carousel, badge or popover.

Measure

Impression and interaction events roll up per widget so you can see which proof actually moves conversion.

Choosing an approach

Guide pages often need to compare options — a compact table works better than paragraphs for that:

ApproachEffortBest for
Embed snippet Lowest Landing pages, Webflow, Framer, WordPress — anywhere you can paste a script tag.
React component Low Next.js and React apps that want theme control without an iframe.
REST API Full control Custom rendering, native apps, or syncing proof into your own database.
Tip

Start with the snippet even if you plan to move to the API later — you can swap rendering layers without touching how proof is collected.
