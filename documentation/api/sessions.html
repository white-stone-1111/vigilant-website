Sessions

Sessions are the API-native way to create the "ask" artifacts — a collection link or a pre-call page — from code. A session wraps the underlying artifact with a stable public id (sess_…), a lifecycle (pending → completed / cancelled / expired), dedupe, idempotency and webhooks, so your integration can create an ask and reconcile what happened to it without scraping the dashboard.

Create a session

POST /api/spaces/{spaceId}/sessions

Registers a new session — the type selects which engine fires.

create-session.sh 
curl -X POST "https://app.endors.io/api/spaces/$SPACE_ID/sessions" \
  -H "Authorization: Bearer $ENDORS_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 8f3a2b1c-checkout-947" \
  -d '{
    "type": "collection",
    "customerName": "Dana Lee",
    "email": "dana@example.com",
    "source": "Stripe Checkout",
    "metadata": {"order_id": "ord_947"}
  }'
FieldTypeRequiredDescription
type string required "collection" (a collection link) or "precall" (a pre-call page).
customerName string For precall The customer's name.
email string For precall; rec. otherwise The customer's email. Required for dedupe — without it, sessions never dedupe. Never emailed by Endors — delivery is yours.
source string optional Free-text attribution (e.g. "Stripe Checkout"). Normalized for dedupe.
templateId string For precall Pre-call template to use (omit for the space default).
context string optional Free-text context for the customer, ≤ 2,000 chars.
metadata object optional Free-form JSON, ≤ 8 KB, returned verbatim on session.completed.
force boolean optional Skip dedupe — always create a fresh session.

Response — 201 Created:

json 
{
  "ok": true,
  "data": {
    "id": "sess_4Nd92kxQ7Tz1mA6vBc8rYt5w",
    "url": "https://collect.endors.io/r/launch",
    "status": "pending",
    "expiresAt": "2026-12-08T16:00:00.000Z",
    "type": "collection",
    "testMode": false,
    "createdAt": "2026-11-08T16:00:00.000Z",
    "deduplicated": false
  }
}

Send url to the customer as-is.

Endors never sends email on your behalf

For any session type, delivering the URL (your own email service, in-app message, SMS…) is your integration's job. The email field exists for dedupe (same email + template + source within 7 days → the existing session returns) and webhook correlation (session.completed / session.opened echo it verbatim) — it is never an address we message. Keeping delivery on your side means deliverability, branding and email compliance stay entirely in your control.

Pre-call sessions draw AI credits

type: "precall" meters 2 AI credits per session from the space's balance. An empty balance returns 402 AI_CREDITS_EXHAUSTED with a paywall payload — retrying the same request cannot succeed until credits are topped up. Details on the Pre-Call pages page.

Deduplication

Within one Space, a session with the same normalized email + template + source created within 7 days of the existing session returns 200 with the existing session and deduplicated: true — no new artifact. Email and source are lowercased/trimmed, so "Stripe Checkout" and "stripe-checkout" dedupe together. A missing email disables dedupe for that request. force: true skips dedupe entirely (and never blocks later dedupe).

Idempotency

Send an Idempotency-Key header to make creation safe against double-clicks and network retries:

  • Same key + same body after completion → the original response is returned verbatim (the same status code and body as the first response).
  • Same key + different body → 409 IDEMPOTENCY_REPLAY_MISMATCH — a caller bug; do not retry with this key.
  • Same key while the first request is still in flight → 409 IDEMPOTENCY_CONFLICT — retryable; wait for Retry-After seconds and send the same key and body again.

Idempotency records are kept for 24 hours.

Test mode

A test-mode key (tick Test mode when creating a key in the dashboard) partitions everything it touches: sessions it creates are flagged testMode: true, skip precall credit drawdown, dedupe only within test mode, and are invisible to live keys in GET. Webhooks still fire, with testMode: true in the envelope. Test sessions are purgeable in one click from the API sessions panel on your dashboard home; the flag itself is fixed at creation — rotate the key to switch modes. See API keys · Test-mode keys.

List sessions

GET /api/spaces/{spaceId}/sessions

Lists sessions, newest first, with keyset pagination.

bash 
curl "https://app.endors.io/api/spaces/$SPACE_ID/sessions?limit=50" \
  -H "Authorization: Bearer $ENDORS_API_KEY"
ParameterTypeDescription
limit integer Page size. Defaults to 50, capped at 200.
cursor string Keyset pagination — pass nextCursor from the previous page; never OFFSET.
type string collection | precall.
status string pending | completed | cancelled | expired.
source string Exact match on the attribution string you sent at creation.
createdAfter ISO 8601 Sessions created after this timestamp.
json 
{
  "ok": true,
  "data": [
    {
      "id": "sess_4Nd92kxQ7Tz1mA6vBc8rYt5w",
      "type": "collection",
      "status": "pending",
      "url": "https://collect.endors.io/r/launch",
      "source": "quickstart",
      "expiresAt": "2026-12-08T16:00:00.000Z",
      "testMode": false,
      "createdAt": "2026-11-08T16:00:00.000Z"
    }
  ],
  "nextCursor": "eyJ2Ijoi…"
}

nextCursor appears only when the page filled. url is the session artifact's live public URL, so you can re-send the same ask to sessions that never completed (the reminder workflow). openedAt appears only once the customer has opened the artifact (absent until then — the funnel is created → opened → completed). A live key never sees test sessions and vice versa.

Get one session

GET /api/spaces/{spaceId}/sessions/{sessionId}

The webhook-less fallback for polling status.

bash 
curl "https://app.endors.io/api/spaces/$SPACE_ID/sessions/sess_4Nd92kxQ7Tz1mA6vBc8rYt5w" \
  -H "Authorization: Bearer $ENDORS_API_KEY"

Response: { ok, data: { id, type, status, url, source, expiresAt, testMode, createdAt, openedAt? } } — same row shape as the list. url is the artifact's live public URL; openedAt appears only once the customer opened it. A pending session past its expiresAt reads as "expired" (sessions auto-expire 30 days after creation). 404 NOT_FOUND for unknown or foreign ids.

Cancel a session

POST /api/spaces/{spaceId}/sessions/{sessionId}/cancel

Expires an unopened session early (wrong trigger, test accident).

bash 
curl -X POST "https://app.endors.io/api/spaces/$SPACE_ID/sessions/sess_4Nd92kxQ7Tz1mA6vBc8rYt5w/cancel" \
  -H "Authorization: Bearer $ENDORS_API_KEY"

Only pending sessions cancel; anything else is 409 INVALID_STATE (a second cancel is also 409, not a silent success). Response: 200 { ok, data: { session: { …, status: "cancelled" } } }.

Session webhooks

Session-created artifacts fire the standard webhooks as the customer moves through the ask — see Supported events. The host's correlation id (sessionId) and the caller's metadata come back on every event:

EventFires when
session.openedThe customer opens the session's artifact (every open while pending).
submission.awaiting_approvalA collection-session submission lands in the Reviews queue.
session.completedThe session's artifact receives its final submission.
