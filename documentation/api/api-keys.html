API keys

API keys give your external applications access to your Endors Space. Each key is scoped to one Space, can be named for easy identification, and can be revoked at any time without affecting other keys.

Limit: 3 keys per Space

Each Space is limited to 3 API keys. You must delete an existing key before creating a new one once the limit is reached.

Creating an API key

  1. Go to Settings → API & Webhooks in your Endors dashboard
  2. Scroll to the API Keys section
  3. Click + New Key
  4. Enter a descriptive name (e.g. zapier-integration, crm-sync, analytics-pipeline)
  5. Optionally tick Test mode — see Test-mode keys below
  6. Click Generate

The full key value is displayed once. Copy it immediately and store it securely. It will not be shown again.

First 2xx without code

The Send test request button next to a freshly created key fires a real request for you — a working API call before you've written any code.

Key format and storage

When a key is created, Endors stores a hashed version of the full key value (never the raw key itself). Each key record exposes a key_prefix — the first 16 characters of the key (e.g. sk_live_a3f2c1d4) — so you can identify which key is which without storing the full value.

text 
sk_live_<48 hex characters>
Never expose your key

Keys in frontend code are visible to anyone who views your page source. Store keys as environment variables on your server (process.env.ENDORS_API_KEY), and if a key is compromised, revoke it immediately from the dashboard and generate a new one.

Test-mode keys

Tick Test mode when creating a key to get a sandbox key in the same Space — the Stripe sk_test_ pattern without a parallel environment. A test-mode key:

  • Creates test sessions — POST /sessions with a test key writes a session flagged testMode: true. Test sessions dedupe only against other test sessions, are invisible to live keys in GET /sessions (and vice versa), skip precall AI-credit metering, and never appear in your library views, stats, or the completion metric on your dashboard home.
  • Still fires webhooks — with testMode: true in the envelope, so you can verify your receiver end-to-end before touching live data.
  • Does not change read access — reads (testimonials, clients, folders, stats) hit the same real library; test mode changes what you write, not what you see.

Test sessions show a test badge on their API key in Settings and are purgeable in one click from the API sessions panel on your dashboard home. The flag is set at creation and cannot be changed — create a new key to switch modes.

Use a test key for your first integration, verify the full round-trip (create → open → complete → webhook), then swap in a live key.

List API keys (dashboard)

From Settings → API & Webhooks, you can see all keys for the active Space, each showing:

  • Name — the label you gave the key
  • Key prefix — the first 16 characters (e.g. sk_live_a3f2c1d4)
  • Test badge — test-mode keys are labeled TEST
  • Last used — when the key last made a successful request (null if never used)
  • Created — when the key was generated
Session-only management

Key management endpoints (list, create, delete) require an active browser session — they do not accept Bearer API keys. Use the dashboard UI to manage your keys.

Key rotation best practice

For production integrations, rotate your API keys periodically:

  1. Generate a new key in the dashboard with the same name + -v2
  2. Update your integration's environment variables to use the new key
  3. Verify the integration is working with the new key
  4. Revoke the old key from the dashboard

Keep the overlap window short (minutes, not days) to minimize exposure if the old key was ever leaked.

Audit: checking when a key was last used

Each key in the dashboard shows a last used timestamp, updated on every successful authenticated request. Use this to identify keys that are no longer active and can safely be revoked.

A null last used timestamp means the key was created but has never been used to make an API request.
