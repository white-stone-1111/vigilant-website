Folders

Folders organize proof inside a space. A testimonial can live in multiple folders at once — membership works like Google Drive's "parents" model and is managed on the testimonial, not the folder.

List folders

GET /api/spaces/{spaceId}/folders

Lists all folders in the space, sorted alphabetically by name. For large folder lists you can paginate with the same optional limit/cursor parameters as the clients endpoint — a request without them returns the full list exactly as before.

Query parameters:

ParameterTypeDescription
name string Case-insensitive substring filter on the folder name.
includeCounts 1 Adds a testimonialCount to every folder.

Request

bash 
curl "https://app.endors.io/api/spaces/$SPACE_ID/folders?includeCounts=1" \
  -H "Authorization: Bearer $ENDOR_API_KEY"

Response

json 
{
  "ok": true,
  "data": [
    { "id": "9c4e…", "name": "Q4 wins", "testimonialCount": 12 }
  ]
}

Pagination (optional)

Identical mechanics to the Clients list: pass limit (capped at 200) to get a nextCursor when the set fills the page, then echo it back as cursor until a response omits it. The keyset rides the list's actual sort key — (name, id) ascending — so pages are stable under inserts/deletes. The same 400 INVALID_LIMIT / 400 INVALID_CURSOR errors apply (with field naming the offending parameter).

Create a folder

POST /api/spaces/{spaceId}/folders

Creates a folder through the same path as the dashboard — write-lock guard and analytics included.

create-folder.sh 
curl -X POST "https://app.endors.io/api/spaces/$SPACE_ID/folders" \
  -H "Authorization: Bearer $ENDOR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "Q4 wins" }'

# → 201 { "ok": true, "data": { "id": "9c4e…", "name": "Q4 wins", … } }

Returns 201 with { ok, data: { id, name, created_at, updated_at } }. A missing or empty name is a 400; a write-locked space is 403 SPACE_LOCKED.

Adding testimonials to folders

Membership lives on the testimonial. Use add_folder_ids / remove_folder_ids on PATCH testimonial — idempotent, validated up front, and both directions can be combined in a single call:

json 
{
  "add_folder_ids": ["9c4e…"],
  "remove_folder_ids": ["1d7f…"]
}
