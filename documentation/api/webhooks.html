Webhooks

Webhooks push events to your backend as things happen in the space. Manage them in the dashboard under Settings → API & Webhooks (creating and editing is session-only); a key can read the current configuration and delivery history.

Reading configuration

GET /api/spaces/{spaceId}/webhooks

Lists webhooks: { ok, data: [ { id, name, url, events, active, created_at } ] }. The signing secret is never returned.

GET /api/spaces/{spaceId}/webhooks/{webhookId}/deliveries

The 20 most recent delivery attempts for a webhook: event, status, attempt_count, response_status, delivered_at.

Events

Verifying signatures

Every delivery is signed with your webhook's secret using HMAC-SHA256. The signature arrives in the X-Endors-Signature and X-Webhook-Signature headers (the latter as sha256=…). Verify over the raw request body:

js 
import crypto from "node:crypto";

export function verifyEndorsSignature(rawBody, signature, secret) {
  const expected = crypto
    .createHmac("sha256", secret)
    .update(rawBody)
    .digest("hex");
  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(signature.replace(/^sha256=/, ""), "hex")
  );
}

Retries & delivery

Failed deliveries retry 5 times with exponential backoff. Inspect outcomes via the deliveries endpoint; a failed or exhausted delivery can be re-attempted from the dashboard.

API writes fire webhooks too

Everything created through the API fires the same webhooks and analytics as the dashboard — e.g. a testimonial created with POST /testimonials fires testimonial.created with source: "api".
