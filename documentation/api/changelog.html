API changelog

Every change to the Endors API and webhooks is announced here — new endpoints, behavioral changes, and deprecations. Additive changes (new endpoints, new optional fields, new error codes) never break existing integrations. Anything that requires action from you is marked Breaking or Behavior change with a deadline and appears here before it takes effect; key owners also receive an email for these.

The compatibility rules behind this page are the versioning policy — in short: additive-only within the current version, and breaking changes ship behind a versioned notice with at least a 12-month overlap window.

2026-11-08 — Sessions API, proof/stats, rate limits, and pagination

Added

The Sessions API is live: POST /sessions creates a collection or pre-call page from code (the artifact factory), with GET /sessions, GET /sessions/{id}, and POST /sessions/{id}/cancel for the lifecycle. Sessions carry context, metadata (echoed on webhooks), source attribution, and dedupe by default (same email + template + source within 7 days returns the existing session with deduplicated: true; pass force: true to override).

GET /proof/stats joins the API — one call for live badges (totalTestimonials, avgRating, videoCount, …), served with a short cache.

Rate limiting is now enforced per API key: 120 requests/minute on reads, 20/minute on AI endpoints (/search, /proof/match, pre-call generation). 429 responses carry RATE_LIMITED and a Retry-After header; every response now carries X-RateLimit-Limit / X-RateLimit-Remaining / X-RateLimit-Reset headers so good clients self-throttle, plus X-Endors-Request-Id for support debugging.

List endpoints (clients, folders, and testimonials when a cursor is passed) gained optional keyset pagination: ?limit=&cursor= with nextCursor in the response. Cursor-less requests return exactly the same sets as before.

Three webhook events joined the set: session.opened, submission.awaiting_approval, and session.completed. The full surface is pinned by an OpenAPI spec and contract tests.

2026-11-08 — Webhook signatures: timestamped scheme (v1) — legacy headers stop 2027-02-01

Breaking

Action required by 2027-02-01

Update your webhook verifier to the timestamped scheme before 2027-02-01. After that date the legacy headers stop being sent and legacy-only verifiers fail closed.

Webhook deliveries now carry a signed timestamp. The canonical scheme is X-Endors-Timestamp (Unix seconds) + X-Endors-Signature-V1: v1=<hex>, where the HMAC input is <timestamp>.<rawBody>. Receivers should reject deliveries whose timestamp is older than ±5 minutes — this bounds the replay window that the legacy body-only signature left open indefinitely.

Until 2027-02-01 both header sets are sent on every delivery, so verifiers for either scheme keep working during the overlap. On 2027-02-01 the legacy X-Endors-Signature: sha256=<hex> (and its X-Webhook-Signature alias) stop being sent and X-Endors-Signature carries the v1 format instead. This is a hard cutover — there is no receiver-side signal other than your deliveries starting to fail verification, so migrate before the date.

If your dashboard delivery log shows failed deliveries with signature-mismatch response bodies, that is the signal you are still on the legacy verifier. The delivery log (Settings → API & Webhooks → Delivery logs) is filterable by status so you can check yourself before the cutover.

Full verifier implementations (Node/Express and Python/Flask) are in the Webhooks API docs under "Verifying webhook signatures".

2026-11-08 — Test-mode keys, delivery-log filters, and the developer changelog

Added

API keys can now be created in test mode (a flag at key creation). Sessions created by a test-mode key are invisible to live keys, never count toward plan limits or metering, and can be purged in one click from the dashboard. Webhooks still fire for test sessions — flagged testMode: true in the payload — so you can verify your handler end-to-end before going live.

The dashboard delivery log gained status and event filters plus the receiver-response snippet for failed deliveries, so post-downtime recovery and verifier debugging happen without contacting support.

The docs gained a Quickstart (key to first 2xx in under five minutes) and a set of trigger-indexed Recipes. This changelog page is now the announcement surface for every API change; breaking changes are also announced by email to key owners (the versioning policy's 12-month overlap promise).
