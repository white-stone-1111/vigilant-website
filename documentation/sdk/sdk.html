@endors/sdk (Node)

The official Node SDK wraps the REST API in a typed, zero-dependency client — full TypeScript types, no dependencies, server-side only (Node ≥ 18). Every path is space-scoped automatically, so you never compose URLs.

For the raw HTTP API, see Overview & Authentication.

Install

bash 
npm install @endors/sdk

Quickstart

quickstart.ts 
import { Endors } from "@endors/sdk";

const endors = new Endors({
  apiKey: process.env.ENDORS_API_KEY, // sk_live_…
  spaceId: process.env.ENDORS_SPACE_ID,
});

// List testimonials (keyset-paginated)
const page = await endors.testimonials.list({ limit: 20 });
const everything = await endors.testimonials.listAll(); // auto-follows nextCursor

// …or iterate lazily — pages are fetched only as the loop advances
for await (const t of endors.testimonials.iterate()) {
  if (t.type === "video") console.log(t.id);
}

// Create a collection session
// NOTE: Endors never sends email on your behalf. The `email` field is for
// dedupe + webhook correlation — delivering `session.url` to the customer
// (your own email, in-app message, SMS…) is your job.
const session = await endors.sessions.create({
  type: "collection",
  email: "customer@acme.com",
  customerName: "Ada Lovelace",
});

// AI proof search
const res = await endors.proof.search({ query: "churn reduced for SaaS teams" });
for (const r of res.answer?.ranked ?? []) console.log(r.label, r.hook);

// Grounded proof matching for a prospect
const match = await endors.proof.match({
  description: "Series A fintech struggling with onboarding drop-off",
  prospect: { industry: "fintech", painPoints: ["onboarding drop-off"] },
});

Configuration

OptionEnv fallbackNotes
apiKey ENDORS_API_KEY sk_live_… secret key. Server-side only.
spaceId ENDORS_SPACE_ID Space all operations are scoped to.
baseUrl — Default https://app.endors.io. Point it at localhost or your own deployment for development.
timeoutMs — Per-attempt timeout (ms). A timeout triggers the normal retry flow with a fresh budget. Not applied to streams.
retry — { maxAttempts, backoffBaseMs, backoffCapMs, onRetry }.

Every resource method also accepts an options object — { signal, timeoutMs, retry, idempotencyKey, headers } — so a per-call timeout or retry override never requires a second client instance:

ts 
await endors.testimonials.list({}, { timeoutMs: 2_000, retry: { maxAttempts: 1 } });

Reliability behavior (built in)

  • Auto-retry on network errors, 429, 5xx, and the retryable error-catalog codes (RATE_LIMITED, IDEMPOTENCY_CONFLICT, DB_ERROR, DELIVERY_FAILED) with exponential backoff + full jitter, honoring Retry-After.
  • Automatic idempotency: every POST carries a generated Idempotency-Key, so a retry after a network failure replays the original response instead of double-creating. Pass your own via { idempotencyKey }.
  • Metered AI endpoints (proof.search, proof.match) are never retried and never auto-keyed — a re-sent POST would double-bill credits.
  • Typed errors: every failure throws an EndorsError with code, status, requestId, retryable, and (on plan gates) paywall. NotFoundError, RateLimitError, CreditsExhaustedError and AuthenticationError are catchable subclasses. requestId is the value you include verbatim when contacting support.
  • Retry observability: set retry.onRetry to see every re-send before it happens — onRetry({ attempt, delayMs, status, code, reason }).
  • Timeouts: timeoutMs bounds each attempt, then throws a typed EndorsError with code "TIMEOUT" (retryable). A caller-supplied AbortSignal always wins (propagates raw). Streams are exempt: timeoutMs bounds time-to-response-headers only; consuming the stream is governed by your own signal.
  • Server-only guard: constructing in a browser logs a loud warning pointing at @endors/widgets — sk_live_ keys must never ship to browsers.

iterate / listAll are available on the four keyset-paginated lists (testimonials, clients, folders, sessions). iterate is a lazy async generator — pages are fetched only as the loop advances, and breaking out stops fetching — so prefer it for anything that might exit early; listAll collects every page into one array.

Streaming

proof.search collects the full answer before resolving. For incremental consumption use proof.searchStream, which yields the same NDJSON events the raw endpoint emits (meta → title/item… → answer → end) — the typed event objects are the same shapes the AI search API documents.

Verifying webhooks

The SDK ships the verifier the API docs describe (freshness check ±5 min, then timing-safe signature compare, legacy scheme handled until the 2027-02-01 cutover):

webhook-route.ts 
import { verifyWebhook } from "@endors/sdk/webhooks";

app.post("/webhooks/endors", express.raw({ type: "application/json" }), (req, res) => {
  const result = verifyWebhook(req.body, req.headers, process.env.ENDORS_WEBHOOK_SECRET);
  if (!result.ok) return res.status(401).send(result.reason);

  const payload = JSON.parse(req.body);
  if (payload.event === "session.completed") {
    // …
  }
  res.sendStatus(200);
});

The full scheme — headers, replay protection, and the cutover timeline — is documented in the Webhooks API page.
